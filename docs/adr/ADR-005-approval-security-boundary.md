# ADR-005：审批 UI 语义与安全边界

- 状态：Proposed / 待 Core 确认
- 日期：2026-10-28
- 责任范围：Harness + Core 安全契约协作

## 背景
用户可能把 UI 上的“拒绝”误解为执行必然停止。客户端只能呈现服务端能力与结果，不能替代 Core 的权限限制和执行约束。

## 暂定建议
审批 UI 至少区分待提交、提交中、已确认、明确失败和结果未知。只有可信服务端确认后才显示已批准/已拒绝。展示审批对象、来源、目标和可获得的风险上下文。不能确认时明确提示，不以颜色或按钮状态暗示安全保证。

## Core 需要确认
拒绝的原子性与执行保证、已排队操作的处理、审批终态、过期语义、审计记录，以及限制会话/授权机制。

## 验证
拒绝请求超时、拒绝后断连、过期审批、并发决策、Core 返回错误、服务端未提供终态等场景。

## 重新评估条件
Core 的审批/执行契约改变，或安全审查发现 UI 表述可能误导用户。
