# ADR-003：终端输出背压与渲染

- 状态：Proposed / Harness 可实现；具体阈值待测量
- 日期：2026-10-28
- 责任范围：Harness 为主，必要时与 Core 协作

## 背景
持续高频输出可能造成桥接消息堆积、UI 卡顿和内存增长。对渲染进行合并不应改变终端数据的字节顺序。

## 暂定建议
先测量当前路径，再实施有界缓冲、分块写入、非关键 UI 更新合并和必要的背压。终端字节保持顺序；关键控制事件不得套用普通日志的静默丢弃策略。任何历史截断需可见。

## 需测指标
输出速率、持续时间、峰值内存、输入延迟、会话切换延迟、窗口响应、队列深度、合并/丢弃计数。

## 验证
持续输出、大块输出、超长单行、多字节文本、输出期间切换会话/关闭窗口、断连重连，以及审批状态在输出洪峰期间变化。

## 重新评估条件
测量显示客户端优化仍无法满足目标，且瓶颈位于 Core 或桥接协议。
