# Termcp Harness 用户侧异常提示与恢复行动（初版）

> 状态：初稿；提示语必须与实际状态、Core/MCP 契约和 Runtime 状态机对齐。本文不是完整的文案治理或国际化规范。
>
> 关联：`docs/product/VISION_v0.9.md`、`docs/architecture/DESIGN_v0.4.md`

## 原则

1. 先说用户需要理解的事实，不直接展示内部枚举名作为主提示。
2. 区分已确认、明确失败和结果未知；不推断未经证实的故障原因。
3. 告诉用户下一步能做什么；操作建议必须适用于用户实际权限和当前功能。
4. 不把 UI 状态描述成服务端安全保证。
5. 提示、按钮状态和恢复操作必须与状态机一致。

## 高风险场景文案

### 1. 执行结果未知

**标题：** 暂时无法确认命令是否执行完成

**说明：** 连接中断前，系统未能取得最终执行结果。该命令可能尚未执行、正在执行，也可能已经执行完成。

**建议操作：** 请先查看当前会话和执行记录，确认实际状态后再决定是否重试。为避免重复操作，系统不会自动重新提交这条命令。

**使用条件：** 仅在服务端结果确实无法确认时使用。如果系统能够证明请求未发送或明确失败，应显示更精确的状态。

### 1.1 工具调用结果未知

**标题：** 暂时无法确认工具是否执行完成

**说明：** Harness 已派发工具调用，但在超时或断连前没有取得可信终态。该调用可能尚未执行、正在执行或已经产生副作用。

**建议操作：** 先查看工具目标、相关终端输出和调用记录；在没有幂等依据时不要立即重试。系统不得自动重复有副作用的调用。

**使用条件：** 仅在调用已派发但终态不可确认时使用。能够证明未派发、明确失败或明确取消时，应显示更精确的状态。

### 1.2 MCP 服务不可用

**标题：** 当前无法使用此 MCP 服务

**说明：** Harness 无法确认该服务的连接、能力或健康状态。之前读取到的工具列表不能自动视为仍然有效。

**建议操作：** 查看服务状态和诊断信息，必要时重新连接；在能力重新确认前，不要依赖旧工具引用继续执行。

**使用条件：** 仅在连接失败、进程退出、版本不兼容或权限不足等有证据的情况下使用，不把普通调用错误误报为服务不可用。

### 1.3 Harness Runtime 不可用

**标题：** 无法连接 Harness Runtime

**说明：** 当前无法确认 Agent、工具调用或 Session 的最新状态。Terminal Workspace 断开不等于 Runtime 或远端任务已经停止。

**建议操作：** 尝试重新连接并刷新 Runtime 状态；恢复前不要重复提交有副作用的操作。

**使用条件：** 仅在 Workspace 与 Runtime 控制通道不可用或身份不兼容时使用。
### 2. 人工与 Agent 输入冲突

**标题：** 当前会话可能正在接收其他输入

**说明：** 检测到 Agent 操作或其他输入活动，但系统无法保证不同来源之间的执行顺序。

**建议操作：** 请检查当前终端输出后再继续。只有 Core 明确支持并确认了互斥/暂停能力时，才能提示已暂停或已取得控制权。

### 3. 审批结果未确认

**标题：** 尚未确认审批结果

**说明：** 系统未能确认 Core 是否接受了这次审批决定。不能据此判断相关操作已被允许或阻止。

**建议操作：** 刷新审批状态或查看当前会话；在结果确认前，不要将该请求视为已批准或已拒绝。

### 4. Core 连接中断

**标题：** 与 Core 的连接已中断

**说明：** 当前无法获取最新会话状态。连接中断本身不能证明远端任务已停止。

**建议操作：** 尝试重新连接并刷新状态。恢复完成前，避免重复提交可能产生副作用的操作。

### 5. 历史记录可能不完整

**标题：** 部分历史记录暂不可用

**说明：** 当前连接或 Core 契约未能确认已恢复断连期间的全部事件。屏幕内容可能不是完整执行历史。

**建议操作：** 刷新会话状态；如果仍无法补齐，请将当前记录视为不完整，不要据此断言某个操作未发生。

### 6. Core 数据目录冲突

**标题：** 无法安全启动此 Core 实例

**说明：** 检测到数据目录或实例归属存在冲突。为避免损坏数据，系统没有自动删除文件或终止未知进程。

**建议操作：** 核对当前实例、数据目录和进程归属后再处理。不要在未确认所有权时手动清理数据。

### 7. 模块依赖或安装组合不可用

**标题：** 当前模块组合无法直接启用

**说明：** 部分模块缺少依赖、存在版本冲突，或属于尚未验证的组合。勾选不代表已安装，安装不代表已启用，启用也不代表当前任务一定可用。Harness Shell 仍然可用，已有模块和 Workspace 不会被静默删除。

**建议操作：** 查看缺失依赖和冲突模块；可以选择补齐依赖、取消受影响模块，或恢复推荐组合。选择未验证组合时，请按提示确认支持边界。

**使用条件：** 仅在模块安装、启用或组合恢复无法满足 Manifest 声明时使用。不得把所有启动失败都归因于模块冲突。

## 文案验收检查

- 是否把“请求已发送”误写为“操作已执行”？
- 是否把“用户点击拒绝”误写为“服务端已阻止执行”？
- 是否在没有证据时将问题归因于网络、Core 崩溃或用户操作？
- 是否区分明确失败与结果未知？
- 给出的下一步是否真实可用，且不会诱导危险的自动重试或破坏性清理？
- 提示是否与当前可获得的 Core 状态字段和能力一致？
- 模块推荐是否被误写成强制安装，依赖和冲突是否被隐藏或含糊处理？
