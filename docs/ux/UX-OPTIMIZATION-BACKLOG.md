## UX-BL-001：跨面板上下文跟随与锁定

**实现状态：** 前端切片、Terminal 真实 Core 上下文切片和实时事件订阅已实现（2026-10-31）。Workspace 可选择当前 Session；Agent、审批、Terminal 和 Activity 面板显示“跟随当前/已锁定/关联未知”，锁定状态随布局持久化。Terminal 只使用可信 `core_session_id` 和 Shell 列表，真实 Session 切换已接入。

**问题**

终端、Agent、审批和 Activity 面板在相邻显示时容易被理解为指向同一任务，实际可能绑定不同 Session、工具调用或审批。切换 Session 后，如果没有显式上下文规则，用户无法判断哪些面板已经切换、哪些仍停留在旧任务。

**候选方案**

- 把“当前 Workspace 默认上下文”和“面板显式上下文”分开建模。
- 面板至少明确显示三种模式：跟随当前 Session、锁定到指定上下文、上下文未绑定或未知。
- 切换 Session 时，只让跟随模式的面板切换；锁定面板必须继续显示原 Session/Task 标识、状态和锁定入口。
- 面板与上下文不能根据标题、相邻位置、时间或终端文本推断关联；缺少可信关联时显示未知。
- 目标 Session 结束、失联或权限变化时，面板进入明确的历史、失效或未知状态，不静默重定向到当前 Session。
- 审批操作继续绑定服务端 `approval_id`、revision 和可信调用关联；本地点击只表示“正在提交决定”。

**触发时机**

开始实现真实 Terminal、实时 Session 切换、审批详情、Activity 时间线或面板标题栏上下文状态时。

**验收要点**

- 同时打开两个 Session，切换当前 Session 后，跟随与锁定面板分别符合声明。
- 锁定目标关闭或失联后，面板不切到其他任务，并显示可恢复入口。
- 审批、Agent 和 Terminal 的上下文标识能够区分不同任务，且关联来源可诊断。
- 缺少 correlation/operation ID 时不补造关联，界面明确显示关联未知。

## UX-BL-002：关闭视图与停止任务彻底分离

**实现状态：** 已实现（2026-11-01）。关闭面板与停止任务已分离：Agent 面板提供受保护停止操作，先显示“正在停止”，只有收到 Runtime 回执后才显示安全取消、远端结果未知或审批仍待处理；关闭面板仍只关闭视图。Workspace 后台任务计数包含 `running`、`cancelling` 和等待审批/执行。模型任务启动和人工恢复改为异步，因此任务运行中仍可选择 Session 并停止。

**问题**

用户关闭面板时容易把“内容消失”理解成“任务已停止”。关闭审批详情也容易被误认为拒绝或取消审批。

**候选方案**

- 面板、模块实例、Agent Session、Core Session、工具调用和审批分别维护生命周期。
- 关闭面板只关闭视图，不取消 Agent、任务、终端 Session 或待处理审批。
- 后台任务在其他位置持续可见，例如全局注意力徽标、任务入口或 Activity；重新打开面板时恢复正确上下文。
- “停止任务”“关闭 Session”“拒绝审批”各自是明确动作，显示影响范围，并以服务端可信回执更新状态。
- 断线时只能显示状态未知；不能把关闭视图写成任务已停止，也不能把审批按钮点击写成服务端已拒绝。

**触发时机**

实现面板关闭提示、全局任务徽标、Session 控制、审批决定或后台任务恢复时。

**验收要点**

- 关闭最后一个 Agent 面板后任务继续运行，并从全局入口可见和重新打开。
- 关闭待审批面板不会拒绝、取消或丢失该审批。
- 停止动作在未收到可信回执前不显示“已停止”；断线后保持未知。

## UX-BL-003：面板身份、模块实例与任务上下文绑定

**实现状态：** 前端切片已实现（2026-10-31）。面板保留稳定 ID，模块 tab 分别保存上下文绑定；Canvas 状态升级为 schema v2，并兼容读取旧布局。跨 Workspace 迁移、任务结束后的归档/重绑和动态模块实例生命周期尚未实现。

**问题**

自由 Canvas 若只保存布局坐标，不保存稳定面板身份和上下文归属，则拖动、标签合并、重启恢复、Workspace 迁移和任务结束清理都会缺少可靠依据，甚至把不同任务的内容重新组合在一起。

**候选方案**

为每个面板建立稳定的逻辑身份，并分别保存：

- 稳定的 `panel_id`；渲染、拖动、缩放、合并标签时不得重新生成。
- 引用的模块实例标识；面板是实例的视图，不应默认拥有模块实例的完整生命周期。
- 显式上下文绑定：Workspace、可空的 Task/Session 关联、关联来源和可信度。
- Task/Session 为全局面板、未绑定或关联未知时使用可序列化的显式空值或未知状态，不按当前活动 Session 自动填充。
- 带版本的 View State；运行时连接句柄、Token 和其他敏感数据与可持久化布局分开。
- 布局和上下文关系的存储修订版本，确保旧异步响应不能覆盖较新的保存结果。

**触发时机**

实现 Workspace 导入导出、版本迁移、跨 Workspace 迁移、任务结束清理、动态模块注册或更复杂标签合并前，需要优先评估本项。

**验收要点**

- 重启、布局恢复、拖动和标签合并后，面板稳定 ID 与上下文绑定不漂移。
- 同一模块实例被多个面板展示时，各视图身份和生命周期边界明确。
- 任务结束后面板进入归档、孤立或可重绑状态，不静默删除仍需恢复的视图状态。
- 跨 Workspace 迁移前检查目标任务可访问性和实时连接重建条件，不迁移虚假运行状态。
- 保存数据不含 Token、Authorization、私钥、远端敏感句柄或其他禁止持久化的内容。

## UX-BL-004：审批与时间线以服务端权威状态收敛

**实现状态：** 前端切片、实时事件切片、`waiting_execution` 人工核对入口和客户端 cursor 持久化已实现（2026-10-31）。审批提交显示“提交中”，成功后才根据服务端回执更新，未知结果保持“结果未知”；每条审批可展开精确 ID 关联的时间线，Activity 仍显示 subject/correlation 并明确标记关联未知。`waiting_execution` 可从受限只读入口重新核对 Core Execution 并触发已有可信证据上的步骤恢复，不重提审批或工具调用。SSE 事件触发合并快照刷新并支持 cursor 重连，仍保留 15 秒兜底轮询；cursor 按 Runtime endpoint 和 instance ID 保存，实例变化时安全重置。真实晚到回执、审批断线专项测试和真实 Wails 进程重启恢复尚未验证。

**问题**

本地按钮状态、乐观更新、事件到达顺序或最后快照都可能被误当成执行事实，导致界面显示成功，而服务端实际未接受或状态已经变化。

**候选方案**

- 审批状态绑定权威 `approval_id`、revision、Session/Task 关联和关联可信度。
- 时间线事件保留事件来源、subject、correlation、sequence 或明确标记缺失，不把接收时间当作执行顺序。
- 提交审批后使用独立“正在提交/等待确认”状态；只有可信服务端回执才能进入批准、拒绝、过期、取消等终态。
- 重连后以服务端快照和补齐后的事件窗口收敛状态；旧 revision 或旧异步结果不得回退新状态。
- 断线、冲突、乱序或关联不明时显示未知，并说明哪些状态不可确认；不得把本地操作直接映射为执行成功。

**触发时机**

接入实时事件订阅、审批详情操作、时间线筛选与关联跳转、断线恢复或结果未知交互时。

**验收要点**

- 点击批准或拒绝后断线，界面显示结果未知，不显示已批准或已拒绝。
- 旧 revision、重复回执和晚到异步结果不会覆盖较新的可信终态。
- 缺少关联 ID 的事件保持关联未知，不根据文本、时间或 Session 名称补造因果关系。
- 重连补齐后，审批和时间线从权威快照进入可解释的一致状态，截断和缺失保持可见。

## UX-BL-005：可序列化状态的版本、迁移与清理

**实现状态：** 部分实现（2026-10-31）。已增加 schema version、旧布局读取兼容、稳定面板 ID、显式上下文绑定、Workspace Recipe v1 导入导出、字段白名单、单面板损坏隔离、导入预览警告、有界撤销/重做、重启后历史恢复和跨 Workspace 布局复制；Recipe 跨版本迁移与跨 Workspace 移动语义仍未实现。

**问题**

稳定 ID 和上下文绑定只有在保存格式可演进、损坏可恢复、敏感数据边界明确时才有长期价值。直接持久化当前前端对象会把内部字段、凭据或不可迁移的运行状态固化进布局。

**候选方案**

- 为 Workspace 与面板上下文结构定义独立 schema version 和最小公开字段。
- 迁移和恢复采用明确、可重试且可诊断的步骤；失败时保留原布局，不静默丢弃面板。
- 持久化视图状态与运行时实例状态分离；恢复后重新验证模块可用性、任务访问权和实时连接。
- 缺失模块、不可访问任务、损坏绑定和版本不兼容分别呈现，不合并为普通加载失败。
- 提供最近可用布局恢复入口，并保证清理操作不会删除仍需审计或恢复的服务端任务事实。

**触发时机**

Workspace 导入导出、持久化格式首次发布、跨版本升级、跨 Workspace 迁移或模块卸载清理流程进入开发时。

**验收要点**

- 旧版本布局可按声明的迁移路径恢复；不可迁移时给出可读原因并保留原数据。
- 损坏的单个面板或上下文绑定不会导致整个 Workspace 无法打开。
- 敏感字段持久化检查通过，运行中句柄不会被恢复成伪造的实时连接。
- 清理只删除明确拥有的本地布局或允许清理的数据，不终止未知进程或删除服务端审计事实。

**当前验证：** Recipe、历史与迁移纯逻辑 Node 回归覆盖往返、Session 引用、损坏面板隔离、重复模块、无效锁定上下文、重叠布局、格式/版本/大小拒绝、安全文件名、撤销/重做、分支清理、容量上限、Workspace 隔离、历史损坏恢复、跨 Workspace 来源不变性和同源/空源拒绝；前端 `tsc`、Vite production build 和完整 Wails production 构建通过。真实 Wails 窗口已验证导出下载并读取正确 JSON；原生文件选择载入 Recipe；无警告预览选择“取消”后原 3 面板布局保持不变；带损坏面板和无效锁定上下文的 Recipe 显示两项修复警告；确认后当前 Workspace 从 3 个面板替换为 2 个，关闭并重启 Desktop 后仍保持导入结果。布局历史另经真实窗口验证：2 面板恢复模板到 3 面板后按钮撤销回 2；`Ctrl+Shift+Z` 重做回 3；Desktop 重启后 `Ctrl+Z` 仍可撤销回 2。跨 Workspace 复制经真实窗口验证：日常协作 2 面板覆盖安全测试 5 面板，预览提示正确，确认后自动切换，目标撤销恢复原 5 面板。

- 个人 Space 数量、名称长度和重名检查有明确上限与可读错误。

## UX-BL-008：状态诚实性与面板/模块命名

**实现状态：** 已实现前端切片（2026-11-02）。MCP `0/0` 使用中性灰；持久化失败显示持续警示和“仅当前会话有效”；Session 汇总中“结果未知”独立计数；当前可组合视图统一使用“面板”，模块术语保留给未来安装与启用生命周期。

**验证证据：** TypeScript 检查、43 项 Node 回归和 Vite production build 通过；Wails 可执行文件重新构建并启动。真实 Wails 自动视觉读取受 Computer Use/WebView2 调试通道限制，尚未完成。

**验收要点**

- 未配置 MCP 不能被显示为就绪。
- localStorage 写入失败时不能继续显示“已保存”。
- `unknown` 不得计入失败或异常。
- 只有完成 Manifest、安装和启用生命周期后，UI 才能把对象称为可安装模块。
